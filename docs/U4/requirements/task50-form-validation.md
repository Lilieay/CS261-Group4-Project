# Task50: U4 - ยืนยันข้อมูลและกติกาฟอร์มเผยแพร่แนวข้อสอบ

**วัตถุประสงค์:** กำหนดฟิลด์ ตัวเลือก และกติกาการตรวจสอบข้อมูลในฟอร์มเผยแพร่แนวข้อสอบ เพื่อให้นักศึกษาสามารถแบ่งปันประสบการณ์สอบ และให้นักศึกษาคนอื่นเปิดอ่านข้อมูลได้ทันทีหลังเผยแพร่สำเร็จ

## 1. รายการฟิลด์ของฟอร์ม

| ลำดับ | ฟิลด์ | ประเภทข้อมูล | สถานะ | รายละเอียด |
|---|---|---|---|---|
| 1 | รายวิชา | Dropdown | บังคับ | เลือกจากรายวิชา CS ที่มีในระบบ |
| 2 | ชื่อแนวข้อสอบ | Text | บังคับ | ชื่อสำหรับแสดงรายการแนวข้อสอบ |
| 3 | ปีการศึกษา | Dropdown | บังคับ | เลือกปี พ.ศ. 2566–2569 |
| 4 | ภาคเรียน | Dropdown | บังคับ | เลือกภาคเรียนที่ 1, 2 หรือฤดูร้อน |
| 5 | ช่วงสอบ | Dropdown | บังคับ | เลือกกลางภาคหรือปลายภาค |
| 6 | หัวข้อที่เคยออกสอบ | Textarea | บังคับ | ระบุหัวข้อที่ผู้เผยแพร่จำได้จากประสบการณ์สอบ |
| 7 | จำนวนข้อสอบ | Number เว้นว่างได้ | เสริม | ระบุจำนวนข้อเป็นจำนวนเต็มบวก หรือเว้นว่างเมื่อไม่ระบุ |
| 8 | รูปแบบข้อสอบ | Dropdown | บังคับ | เลือกหนึ่งค่า ได้แก่ ปรนัย อัตนัย หรือผสม |
| 9 | คำแนะนำในการเตรียมสอบ | Textarea | เสริม | แบ่งปันคำแนะนำหรือข้อมูลเพิ่มเติม |


## 2. ตัวเลือกของฟิลด์

| ฟิลด์ | ตัวเลือกหรือข้อกำหนด |
|---|---|
| รายวิชา | เลือกจากรหัสวิชา CS ที่มีอยู่ในระบบ |
| ปีการศึกษา | 2566, 2567, 2568, 2569 |
| ภาคเรียน | 1, 2, ฤดูร้อน |
| ช่วงสอบ | กลางภาค, ปลายภาค |
| จำนวนข้อสอบ | จำนวนเต็มมากกว่า 0 หรือไม่ระบุ |
| รูปแบบข้อสอบ | ปรนัย, อัตนัย, ผสม |

## 3. กติกาการตรวจสอบข้อมูล

### 3.1 การตรวจสอบฟิลด์บังคับ

1. ต้องระบุรายวิชา ชื่อแนวข้อสอบ ปีการศึกษา ภาคเรียน ช่วงสอบ หัวข้อที่เคยออกสอบ และรูปแบบข้อสอบให้ครบ
2. ชื่อแนวข้อสอบและหัวข้อที่เคยออกสอบต้องไม่เป็นค่าว่างหรือมีเฉพาะช่องว่าง
3. ชื่อแนวข้อสอบยาวไม่เกิน 200 ตัวอักษร หัวข้อและคำแนะนำเพิ่มเติมยาวไม่เกินช่องละ 2,000 ตัวอักษร
4. ต้องเลือกรูปแบบข้อสอบหนึ่งค่า
5. หากข้อมูลไม่ครบ ต้องแสดงข้อความแจ้งฟิลด์ที่ต้องแก้ไข โดยไม่สร้างรายการใหม่
6. เมื่อข้อมูลไม่ผ่านการตรวจสอบ ควรเก็บข้อมูลฟิลด์อื่นที่ผู้ใช้กรอกไว้เพื่อให้แก้ไขต่อได้

### 3.2 การตรวจสอบค่าที่เลือก

1. รายวิชาต้องเป็นรายวิชา CS ที่มีอยู่ในระบบ ห้ามสร้างรายวิชาใหม่จากการส่งฟอร์ม
2. ปีการศึกษาต้องอยู่ระหว่าง พ.ศ. 2566–2569
3. ภาคเรียนต้องเป็น 1, 2 หรือฤดูร้อน
4. ช่วงสอบต้องเป็นกลางภาคหรือปลายภาค
5. รูปแบบข้อสอบต้องเป็นปรนัย อัตนัย หรือผสม
6. Backend ต้องตรวจสอบค่าที่ส่งมาอีกครั้ง ไม่เชื่อถือเฉพาะการตรวจสอบจากหน้าเว็บ

### 3.3 การตรวจสอบจำนวนข้อสอบ

1. อนุญาตให้เว้นว่างเมื่อไม่ระบุจำนวนข้อสอบได้
2. หากระบุจำนวนข้อสอบ ต้องเป็นจำนวนเต็มมากกว่า 0
3. ต้องปฏิเสธค่า 0, จำนวนติดลบ, ทศนิยม และข้อความที่ไม่ใช่จำนวน
4. เมื่อเว้นว่าง ให้ส่ง `null` และแสดงว่าไม่ระบุ ไม่แทนค่าด้วย 0
5. รูปแบบปรนัยรับเฉพาะจำนวนข้อปรนัย รูปแบบอัตนัยรับเฉพาะจำนวนข้ออัตนัย ส่วนแบบผสมรับได้ทั้งสองจำนวน โดยแต่ละจำนวนยังเลือกไม่ระบุได้

### 3.4 การตรวจสอบเจ้าของรายการและสถานะ Login

1. ผู้เผยแพร่ต้องเข้าสู่ระบบก่อนส่งข้อมูล
2. เจ้าของรายการต้องอ้างอิงจากบัญชีผู้ใช้ที่ผ่านการยืนยันตัวตนจาก Backend
3. ไม่ให้ผู้ใช้กำหนดเจ้าของรายการผ่านฟอร์มเอง
4. หากสถานะ Login ใช้ไม่ได้ Backend ต้องปฏิเสธการเผยแพร่ และหน้าเว็บแจ้งให้ Login ใหม่

### 3.5 การบันทึกและเผยแพร่

1. เมื่อข้อมูลผ่านการตรวจสอบและบันทึกสำเร็จ ให้สร้างรายการแนวข้อสอบเพียงหนึ่งรายการต่อการส่งหนึ่งครั้ง
2. แสดงข้อความแจ้งสำเร็จและเปิดหน้ารายละเอียดของรายการที่เผยแพร่
3. รายการต้องปรากฏในหน้ารายวิชาและหน้ารายการของผู้เผยแพร่
4. นักศึกษาคนอื่นที่ Login สามารถอ่านรายการได้ทันทีโดยไม่ต้องรออนุมัติ
5. ข้อมูลต้องยังคงอยู่หลังโหลดหน้าใหม่
6. หากบันทึกล้มเหลว ต้องไม่แสดงข้อความว่าสำเร็จ และต้องไม่มีข้อมูลที่บันทึกค้างไว้บางส่วน


## 4. ผลลัพธ์ที่คาดหวัง

- ข้อมูลไม่ครบหรือไม่ถูกต้อง: แจ้งข้อผิดพลาดและไม่สร้างรายการ
- ข้อมูลถูกต้องและบันทึกสำเร็จ: เผยแพร่รายการและเปิดอ่านได้ทันที
- ผู้เผยแพร่และนักศึกษาคนอื่นที่ Login สามารถเปิดอ่านข้อมูลตามสิทธิ์ที่กำหนด
- ข้อมูลเจ้าของรายการต้องตรงกับบัญชีผู้ใช้ที่ผ่านการยืนยันตัวตน
- เมื่อบันทึกล้มเหลว ระบบต้องไม่แสดงว่าการเผยแพร่สำเร็จ

## 5 การอ้างอิงและขอบเขตการรับประกัน

รูปแบบข้อมูลและข้อผิดพลาดของ API ดู [Task52](../design/task52-publish-guide-api-spec.md) Backend ตรวจสอบข้อมูลก่อนบันทึกและ rollback เมื่อการบันทึกล้มเหลว แต่หากการเชื่อมต่อขาดหลังบันทึกสำเร็จ ผู้ใช้อาจยังไม่ได้รับคำตอบ จึงต้องตรวจรายการก่อนส่งซ้ำ API ปัจจุบันยังไม่รับประกันว่าการส่งซ้ำจะไม่สร้างรายการซ้ำ
