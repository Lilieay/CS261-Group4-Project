# Task61: U4 — UAT และเตรียมสาธิตการเผยแพร่แนวข้อสอบ

เอกสารนี้เป็นแผนและแบบบันทึก UAT สำหรับฟังก์ชันเผยแพร่แนวข้อสอบ ผู้ทดสอบต้องกรอกผลจริงและแนบหลักฐานหลังทดสอบจริง ส่วนผลคาดหวังในเอกสารนี้ยังไม่ถือเป็นผล Demo หรือผลตรวจรับจาก PO

## 2. ข้อมูลและเงื่อนไขก่อนทดสอบ

### ข้อมูลทดสอบสำเร็จ

- บัญชีนักศึกษาที่เข้าสู่ระบบได้: ใช้บัญชีทดสอบของทีม ห้ามใส่รหัสผ่านจริงลงในเอกสาร
- รายวิชา: `CS261`
- ชื่อแนวข้อสอบ: `แนวข้อสอบกลางภาค CS261 สำหรับทดสอบ UAT`
- ปีการศึกษา: `2569`
- ภาคเรียน: `1`
- ช่วงการสอบ: `กลางภาค (Midterm)`
- รูปแบบข้อสอบ: `ผสม (ปรนัย + อัตนัย)`
- จำนวนข้อปรนัย: `10`
- จำนวนข้ออัตนัย: `5`
- หัวข้อที่ออกสอบ: `Requirements, UML และ Software Testing`
- คำแนะนำเพิ่มเติม: `ข้อมูลสำหรับการสาธิตเท่านั้น`

### ข้อมูลทดสอบไม่ผ่าน

- เว้นชื่อแนวข้อสอบหรือใส่เฉพาะช่องว่าง
- เว้นรายวิชา ปีการศึกษา ภาคเรียน ช่วงสอบ รูปแบบข้อสอบ หรือหัวข้อ
- ใส่จำนวนข้อเป็น `0`, `-1`, `2.5` หรือข้อความที่ไม่ใช่จำนวนเต็ม
- ใช้ข้อมูลรายวิชาที่ไม่มีอยู่หรืออยู่นอกขอบเขต เช่น `CS999` หรือ `MA111` เมื่อทดสอบผ่าน API
- ปิด Backend/ทำให้ Login หมดอายุ เพื่อดูการแจ้งข้อผิดพลาด

### เงื่อนไขที่ต้องเตรียม

1. ใช้โค้ดรุ่นเดียวกันทั้ง Frontend และ Backend และจด commit ไว้ในหัวข้อข้อมูลการตรวจรับ
2. ตรวจว่า Backend เปิดอยู่ที่ port `8000`, Login endpoint ใช้งานได้ และมี CS261 ในฐานข้อมูลจริง
3. ตรวจว่า `GuidePublishConfig.mode` เป็น `api` และบันทึก ID ของรายการที่เผยแพร่จากคำตอบ API เพื่อใช้ตรวจซ้ำ
4. เปิด DevTools ได้เฉพาะเพื่อดูสถานะคำขอ ห้ามถ่ายหรือบันทึก password, access token หรือข้อมูลลับ

## 3. เกณฑ์การตรวจรับ

ถือว่าผ่านเมื่อระบบทำได้ครบตามข้อเหล่านี้:

- ผู้ใช้ที่ Login แล้วเลือกวิชา CS และกรอกข้อมูลที่จำเป็นครบ สามารถกดเผยแพร่ได้
- ระบบส่งข้อมูลตามรูปแบบที่กำหนด และแสดงข้อความสำเร็จ/ลิงก์ไปยังรายละเอียดรายการ
- รายละเอียดที่แสดงตรงกับข้อมูลที่กรอก รวมถึงจำนวนข้อ หัวข้อ ผู้เผยแพร่ และคำแนะนำถ้ามี
- ช่องบังคับและจำนวนข้อที่ไม่ถูกต้องถูกแจ้งก่อนบันทึก หรือ Backend ปฏิเสธอย่างเหมาะสม
- เมื่อ Login ใช้ไม่ได้, Backend ล่ม หรือบันทึกล้มเหลว ระบบไม่แสดงว่าสำเร็จ และไม่สร้างรายการซ้ำโดยไม่ยืนยันผล
- การเผยแพร่ต้องบันทึกลงฐานข้อมูลจริง และนักศึกษาอีกบัญชีที่ Login ต้องเปิดอ่านรายการนั้นได้
- ไม่มี password หรือ access token ปรากฏในเอกสาร ภาพหลักฐาน Console หรือ Postman Collection

## 5. Demo Script สำหรับสาธิต

### 5.1 เตรียมก่อนเริ่ม Demo

1. เตรียมบัญชีทดสอบและข้อมูลตามหัวข้อ 2 โดยไม่ใช้รหัสผ่านจริงบนหน้าจอหรือในเอกสาร
2. เปิด Backend และ Frontend ตาม URL ที่ระบุในหัวข้อ 1
3. ตรวจโหมด `api` และใช้ CS261 ที่ได้จาก Course API สำหรับการสาธิต
4. ใช้ชื่อรายการที่มี timestamp เพื่อแยกข้อมูล UAT จากรายการเดิม โดยไม่ล้างข้อมูลผู้ใช้
5. เปิดหน้า Login และเตรียมหน้ารายละเอียดรายวิชาไว้เป็นแท็บสำรอง

### 5.2 ลำดับการสาธิตกรณีสำเร็จ

| ลำดับ | ผู้สาธิตทำอะไร | สิ่งที่ควรเห็น |
|---|---|---|
| 1 | Login ด้วยบัญชีทดสอบ | เข้าสู่ระบบสำเร็จ และไปหน้ารายวิชาได้ |
| 2 | เปิดหน้าเผยแพร่แนวข้อสอบ | ฟอร์มพร้อมใช้งาน และชื่อผู้ใช้แสดงถูกต้อง |
| 3 | เลือก `CS261` และกรอกข้อมูลสำเร็จครบทุกช่อง | ค่าที่กรอกแสดงครบ ไม่มี error ใต้ช่อง |
| 4 | กด `เผยแพร่` หนึ่งครั้ง | ปุ่มแสดงสถานะกำลังบันทึก แล้วจบด้วยข้อความสำเร็จ |
| 5 | เปิดลิงก์รายละเอียดที่ระบบให้ | รายละเอียดตรงกับชื่อ ปี ภาคเรียน รูปแบบ จำนวนข้อ หัวข้อ และผู้เผยแพร่ |
| 6 | โหลดหน้าใหม่/กลับเข้าหน้ารายวิชา | รายการยังอยู่ในฐานข้อมูลจริง และไม่เกิดรายการซ้ำ |

### 5.3 ลำดับการสาธิตกรณีข้อมูลไม่ครบ

1. กลับไปหน้าเผยแพร่และกรอกข้อมูลให้ครบก่อนหนึ่งครั้ง
2. ลบชื่อแนวข้อสอบ แล้วกดเผยแพร่
3. ชี้ให้เห็นข้อความแจ้งเตือนใต้ช่องและยืนยันว่าไม่มีรายการใหม่ถูกสร้าง
4. ใส่ชื่อกลับ แล้วเปลี่ยนจำนวนข้อเป็น `0` หรือค่าที่ไม่ใช่จำนวนเต็ม
5. กดเผยแพร่และชี้ให้เห็นว่าระบบยังไม่บันทึก พร้อมคงข้อมูลในฟอร์มไว้แก้ไข

### 5.4 ลำดับการสาธิตกรณีระบบ/การ Login มีปัญหา

1. หยุด Backend หรือทำให้ token หมดอายุตามวิธีที่ทีมเตรียมไว้
2. กรอกข้อมูลสำเร็จแล้วกดเผยแพร่
3. แสดงข้อความผิดพลาดที่เข้าใจได้ และยืนยันว่าไม่มีข้อความ “เผยแพร่สำเร็จ”
4. เปิด Backend/ให้ Login ใหม่ แล้วตรวจรายการก่อนกดส่งซ้ำ เพื่อป้องกันข้อมูลซ้ำ

## 6. สิ่งที่ต้องเห็นในตอนจบ Demo

- กรณีสำเร็จแสดงรายการและรายละเอียดที่ตรงกับข้อมูลทดสอบ
- กรณีข้อมูลผิดพลาดถูกหยุดพร้อมข้อความที่บอกวิธีแก้
- กรณีระบบขัดข้องไม่ถูกหลอกว่าเผยแพร่สำเร็จ
- หลักฐานแสดงการเรียก API และรายการที่บันทึกในระบบจริง โดยไม่เปิดเผย token
- มีการบันทึกผลจริง หลักฐาน และการตัดสินใจของ PO แยกจากผลคาดหวังในเอกสารนี้
