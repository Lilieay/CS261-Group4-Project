# Task54: U4 — เตรียมแผนทดสอบการเผยแพร่แนวข้อสอบ

## 1. วัตถุประสงค์

เพื่อทดสอบการเผยแพร่แนวข้อสอบผ่านฟอร์มบนเว็บไซต์ ตั้งแต่การกรอกข้อมูล การตรวจสอบข้อมูลบังคับและข้อมูลเสริม การบันทึกข้อมูล การกำหนดเจ้าของรายการ ไปจนถึงการแสดงรายการที่เผยแพร่ให้นักศึกษาคนอื่นอ่านได้

## 2. ขอบเขตการทดสอบ

1. **UI Test:** ทดสอบฟอร์มเผยแพร่ การตรวจสอบข้อมูล และข้อความแจ้งผล
2. **API Test:** ทดสอบการส่งข้อมูลเผยแพร่และการจัดการข้อมูลที่ไม่ถูกต้อง
3. **DAO Test:** ทดสอบการบันทึกข้อมูล การกำหนดเจ้าของ และความถูกต้องของข้อมูลในฐานข้อมูล
4. **UI-API Test:** ทดสอบการทำงานร่วมกันระหว่างฟอร์มกับ API
5. **API-DAO Test:** ทดสอบการส่งข้อมูลจาก API ไปบันทึกในฐานข้อมูลและรับผลกลับ
6. **System Test:** ทดสอบกระบวนการเผยแพร่ตั้งแต่กรอกฟอร์มจนถึงเปิดอ่านรายการ
7. **UAT:** ให้ผู้ใช้ตรวจสอบว่าการเผยแพร่แนวข้อสอบตอบโจทย์ User Story และ Definition of Done

## 3. ข้อมูลตั้งต้นและเงื่อนไขก่อนทดสอบ

- มีบัญชีนักศึกษาที่เข้าสู่ระบบได้
- มีรายวิชา CS261 อยู่ในระบบ มีรหัสสมมติที่ไม่มีในระบบ เช่น CS999 และเตรียมรายวิชานอกขอบเขต เช่น MA111 เฉพาะในฐานข้อมูลทดสอบ
- ฟอร์มมีช่องวิชา ชื่อแนวข้อสอบ ปีการศึกษา ภาคเรียน ช่วงสอบ หัวข้อ รูปแบบข้อสอบ จำนวนข้อ และคำแนะนำ
- กำหนดข้อมูลที่ระบบยอมรับไว้ล่วงหน้า ได้แก่ ปี 2566–2569 ภาคเรียน 1, 2 และฤดูร้อน ช่วงกลางภาคและปลายภาค และรูปแบบปรนัย อัตนัย และผสม
- เตรียมบัญชีนักศึกษาอีกคนเพื่อทดสอบการอ่านและการกำหนดเจ้าของรายการ
- เตรียมวิธีทดสอบกรณี Backend ปฏิเสธข้อมูล สถานะ Login ใช้ไม่ได้ และการบันทึกล้มเหลว

## 4. Test Cases Specification

### U4-TC01: เผยแพร่สำเร็จและนักศึกษาอื่นอ่านได้ทันที

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้ว และมีข้อมูลแนวข้อสอบ CS261 ที่กรอกครบและถูกต้อง

**วิธีทดสอบ**
1. กรอกข้อมูลแนวข้อสอบ CS261 ให้ครบ
2. กดเผยแพร่หนึ่งครั้ง
3. ตรวจสอบข้อความแจ้งผลและหน้าอ่าน
4. ตรวจสอบรายการในหน้ารายวิชาและหน้า “ของฉัน”
5. โหลดหน้าใหม่ แล้วเข้าสู่ระบบด้วยบัญชีนักศึกษาอีกคนเพื่อเปิดอ่านรายการ

**ผลที่คาดหวัง**
- สร้างแนวข้อสอบเพียงหนึ่งรายการ โดยผู้ที่เข้าสู่ระบบเป็นเจ้าของ
- แจ้งเผยแพร่สำเร็จและเปิดหน้าอ่านตรงกับข้อมูลที่กรอก
- รายการปรากฏในหน้ารายวิชาและหน้า “ของฉัน”
- นักศึกษาคนอื่นที่เข้าสู่ระบบแล้วสามารถอ่านได้ทันทีโดยไม่ต้องรออนุมัติ
- ข้อมูลยังคงอยู่หลังโหลดหน้าใหม่

### U4-TC02: เผยแพร่ได้โดยไม่กรอกข้อมูลเสริม

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้วและกรอกข้อมูลบังคับครบถ้วน

**วิธีทดสอบ**
1. กรอกข้อมูลบังคับให้ครบ
2. เลือกจำนวนข้อเป็น “ไม่ระบุ”
3. เว้นช่องผู้สอนและคำแนะนำ
4. กดเผยแพร่และเปิดอ่านรายการ

**ผลที่คาดหวัง**
- เผยแพร่ได้ตามปกติ
- ข้อมูลหลักยังครบถ้วน
- จำนวนข้อและผู้สอนแสดงว่าไม่ระบุ ไม่แทนด้วย 0 หรือผู้สอนสมมติ
- คำแนะนำที่ว่างไม่ทำให้หน้าอ่านผิดพลาด

### U4-TC03: ไม่เผยแพร่เมื่อขาดข้อมูลบังคับ

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้ว และมีข้อมูลฟอร์มที่กรอกครบถูกต้องสำหรับใช้เริ่มต้นแต่ละรอบ

**วิธีทดสอบ**
1. กรอกข้อมูลให้ครบ
2. เว้นช่องวิชาแล้วลองเผยแพร่
3. เริ่มรอบใหม่โดยเว้นชื่อแนวข้อสอบ
4. ทำซ้ำโดยเว้นปีการศึกษา ภาคเรียน ช่วงสอบ หัวข้อ และรูปแบบข้อสอบทีละช่อง
5. ตรวจสอบข้อความแจ้งเตือน ข้อมูลฟอร์ม และรายการที่ถูกบันทึก

**ผลที่คาดหวัง**
- ทุกกรณีแจ้งช่องที่ต้องกรอก
- ไม่สร้างรายการและไม่แจ้งเผยแพร่สำเร็จ
- ข้อมูลเดิมไม่เปลี่ยนแปลง
- ข้อมูลช่องอื่นในฟอร์มยังอยู่เพื่อให้แก้ไขต่อได้

### U4-TC04: ชื่อหรือหัวข้อมีแต่ช่องว่างถือว่ายังไม่ได้กรอก

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้วและกรอกข้อมูลอื่นครบถ้วน

**วิธีทดสอบ**
1. ใส่ช่องว่างล้วนในช่องชื่อแนวข้อสอบ แล้วลองเผยแพร่
2. เริ่มรอบใหม่และใส่ช่องว่างล้วนในช่องหัวข้อ
3. ทดสอบส่งข้อมูลลักษณะเดียวกันตรงไปยัง Backend โดยไม่ผ่านการตรวจสอบบนหน้าเว็บ
4. ตรวจสอบผลตอบกลับและข้อมูลที่บันทึก

**ผลที่คาดหวัง**
- ระบบระบุช่องที่ต้องแก้ไข
- ปฏิเสธข้อมูลที่มีเพียงช่องว่าง ทั้งจากฟอร์มและ Backend
- ไม่สร้างรายการใหม่

### U4-TC05: จำนวนข้อที่ระบุต้องเป็นจำนวนเต็มมากกว่า 0

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้วและกรอกข้อมูลอื่นถูกต้อง

**วิธีทดสอบ**
1. ทดลองส่งจำนวนข้อเป็น 0
2. ทดลองส่งจำนวนข้อเป็น -1
3. ทดลองส่งจำนวนข้อเป็น 2.5
4. ทดลองส่งจำนวนข้อเป็น “สิบ”
5. ทดสอบผ่านฟอร์มและ Backend ตามช่องทางที่สามารถส่งค่าได้
6. ทดลองเลือก “ไม่ระบุ” แยกต่างหาก

**ผลที่คาดหวัง**
- ปฏิเสธค่า 0, -1, 2.5 และ “สิบ”
- แจ้งให้กรอกจำนวนเต็มมากกว่า 0 หรือเลือกไม่ระบุ
- ไม่สร้างรายการและไม่เปลี่ยนค่าที่ไม่ถูกต้องเป็น 0 โดยไม่แจ้ง
- ตัวเลือก “ไม่ระบุ” ใช้งานได้ตามปกติ

### U4-TC06: ไม่รับค่าปี ภาคเรียน ช่วงสอบหรือรูปแบบที่ไม่มีในตัวเลือก

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้วและกรอกข้อมูลอื่นถูกต้อง โดยระบบมีชุดค่าที่อนุญาตสำหรับปีการศึกษา ภาคเรียน ช่วงสอบ และรูปแบบข้อสอบ

**วิธีทดสอบ**
1. ส่งปี 2565 และ 2570 ซึ่งอยู่นอกช่วง 2566–2569 และทดสอบว่าปีขอบเขต 2566 กับ 2569 ใช้ได้
2. เริ่มรอบใหม่และส่งค่าภาคเรียนที่ไม่ใช่ 1, 2 หรือฤดูร้อน
3. ทดลองส่งช่วงสอบที่ไม่ใช่กลางภาคหรือปลายภาค
4. ทดลองส่งรูปแบบอื่น เช่น `other` ซึ่งต้องถูกปฏิเสธ
5. ส่งข้อมูลตรงไปยัง Backend และตรวจสอบผล

**ผลที่คาดหวัง**
- ปฏิเสธค่าที่ไม่อยู่ในชุดข้อมูลที่อนุญาต
- ไม่สร้างรายการหรือเพิ่มตัวเลือกใหม่เอง
- ไม่เปลี่ยนข้อมูลที่ไม่ถูกต้องเป็นค่าอื่นโดยไม่แจ้ง

### U4-TC07: เผยแพร่ให้วิชาที่ไม่มีในระบบหรือนอกขอบเขตไม่ได้

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้ว และระบบมีเฉพาะรายวิชารหัส CS ที่ทีมเตรียมไว้

**วิธีทดสอบ**
1. กรอกข้อมูลแนวข้อสอบโดยระบุวิชา CS999 ซึ่งไม่มีในระบบ
2. เริ่มรอบใหม่และระบุวิชา MA111 ซึ่งอยู่นอกขอบเขต
3. ส่งข้อมูลผ่าน Backend เพื่อทดสอบการตรวจสอบฝั่งเซิร์ฟเวอร์
4. ตรวจสอบรายการที่บันทึกและข้อมูลรายวิชา

**ผลที่คาดหวัง**
- ระบบแจ้งให้เลือกวิชาที่มีอยู่ในระบบและอยู่ในขอบเขต
- ไม่สร้างแนวข้อสอบหรือรายวิชาใหม่
- ข้อมูลเดิมไม่เปลี่ยนแปลง

### U4-TC08: เผยแพร่โดยอ้างผู้อื่นเป็นเจ้าของไม่ได้

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้ว มีบัญชีของนักศึกษาอีกคน และมีข้อมูลแนวข้อสอบที่ถูกต้อง

**วิธีทดสอบ**
1. กรอกข้อมูลแนวข้อสอบให้ครบ
2. ส่งข้อมูลไปยัง Backend โดยระบุบัญชีของนักศึกษาอีกคนเป็นเจ้าของ
3. ตรวจสอบผลตอบกลับและข้อมูลในฐานข้อมูล
4. เผยแพร่ตามปกติโดยไม่ระบุเจ้าของในฟอร์ม

**ผลที่คาดหวัง**
- Backend ไม่อนุญาตให้กำหนดผู้อื่นเป็นเจ้าของแทนผู้ที่เข้าสู่ระบบ
- ไม่สร้างรายการที่มีเจ้าของไม่ถูกต้อง
- การเผยแพร่ตามปกติกำหนดเจ้าของจากบัญชีที่เข้าสู่ระบบ
- ฟอร์มไม่เปิดให้ผู้ใช้กำหนดเจ้าของรายการเอง

### U4-TC09: บันทึกล้มเหลวต้องไม่แสดงว่าเผยแพร่สำเร็จ

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษาเข้าสู่ระบบแล้วและกรอกข้อมูลถูกต้อง พร้อมวิธีจำลองให้การบันทึกล้มเหลว

**วิธีทดสอบ**
1. กรอกข้อมูลแนวข้อสอบให้ครบ
2. จำลองความล้มเหลวในขั้นตอนบันทึกข้อมูล
3. กดเผยแพร่
4. ตรวจสอบข้อความแจ้งผล ข้อมูลในฟอร์ม หน้ารายวิชา หน้า “ของฉัน” และฐานข้อมูล

**ผลที่คาดหวัง**
- ระบบแจ้งว่าบันทึกไม่สำเร็จและให้ลองใหม่
- ไม่แจ้งว่าเผยแพร่สำเร็จ
- ข้อมูลในฟอร์มยังอยู่เพื่อให้ลองใหม่ได้
- ไม่มีรายการใหม่หรือข้อมูลที่บันทึกค้างเพียงบางส่วน

### U4-TC10: สถานะ Login ใช้ไม่ได้ก่อนเผยแพร่

**ประเภทการทดสอบ:** UI, API, DAO, UI-API, API-DAO, System Test, UAT

**ข้อมูลตั้งต้น:** นักศึกษากรอกฟอร์มครบแล้ว แต่สถานะ Login หมดอายุหรือใช้ไม่ได้ก่อนส่งข้อมูล

**วิธีทดสอบ**
1. เข้าสู่ระบบและกรอกข้อมูลแนวข้อสอบให้ครบ
2. ทำให้สถานะ Login ใช้ไม่ได้ก่อนกดเผยแพร่
3. กดเผยแพร่และตรวจสอบผลตอบกลับจาก Backend
4. ตรวจสอบรายการที่สร้างและเจ้าของรายการ

**ผลที่คาดหวัง**
- Backend ปฏิเสธการเผยแพร่
- หน้าเว็บแจ้งให้เข้าสู่ระบบใหม่
- ไม่สร้างรายการและไม่ผูกผลงานกับบัญชีอื่น
- ไม่แจ้งเผยแพร่สำเร็จ
