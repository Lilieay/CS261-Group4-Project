# Task83: U5 — UAT และเตรียมสาธิตการจัดการแนวข้อสอบ

เอกสารนี้เป็นแผนและแบบบันทึก UAT สำหรับการดู เปิดอ่าน แก้ไข และลบแนวข้อสอบของผู้ใช้เอง ผู้ทดสอบต้องกรอกผลจริงและแนบหลักฐานหลังทดสอบ ส่วนผลคาดหวังในเอกสารนี้ยังไม่ถือเป็นผล Demo หรือผลตรวจรับจาก PO

## 2. ข้อมูลและเงื่อนไขก่อนทดสอบ

### ข้อมูลทดสอบ

- บัญชีนักศึกษาคนที่ 1: บัญชีทดสอบของเจ้าของรายการ ห้ามใส่รหัสผ่านจริงในเอกสาร
- บัญชีนักศึกษาคนที่ 2: บัญชีทดสอบที่ไม่ใช่เจ้าของรายการ
- รายการตั้งต้น: รายวิชา `CS261`, ชื่อ `แนวข้อสอบ CS261 สำหรับทดสอบการจัดการ`, ปีการศึกษา `2569`, ภาคเรียน `1`, ช่วงสอบ `กลางภาค`, รูปแบบ `ปรนัย + อัตนัย`, จำนวนปรนัย `10`, จำนวนอัตนัย `5`
- ข้อมูลที่จะเปลี่ยน: ชื่อเป็น `แนวข้อสอบ CS261 ฉบับแก้ไข UAT`, รายวิชาใหม่ `CS102` ที่มีในชุด seed, หัวข้อ `หัวข้อที่แก้ไขเพื่อทดสอบ`, คำแนะนำ `แก้ไขแล้ว`
- ข้อมูลผิดพลาด: ชื่อว่าง/ช่องว่างล้วน, หัวข้อว่าง, จำนวน `0` หรือ `-1`, รายวิชาไม่มีอยู่ เช่น `CS999`

### เงื่อนไขที่ต้องเตรียม

1. สร้างรายการตั้งต้นของเจ้าของอย่างน้อย 1 รายการ และมีรายการของผู้ใช้อื่นอย่างน้อย 1 รายการสำหรับตรวจสอบสิทธิ์
2. เตรียมรายการอีกหนึ่งรายการไว้ยืนยันว่าการแก้ไขหรือลบรายการหนึ่งไม่กระทบรายการอื่น
3. เปิด Backend ที่ port `8000`, ตรวจว่า CS261 และ CS102 มีอยู่ในฐานข้อมูล และ Login endpoint ใช้งานได้
4. เผยแพร่รายการทดสอบผ่านฟอร์มจริง และบันทึก ID จาก API เพื่อตรวจรายการเดิมหลังแก้ไขหรือย้ายวิชา
5. จด commit ที่ใช้ทดสอบ และห้ามแสดง password, access token หรือข้อมูลลับในภาพหลักฐาน/Console

## 3. เกณฑ์การตรวจรับ

ถือว่าผ่านเมื่อระบบทำได้ครบตามข้อเหล่านี้:

- ผู้ใช้ Login แล้วเห็นเฉพาะแนวข้อสอบที่ตนเองเป็นเจ้าของในหน้า “แนวข้อสอบของฉัน”
- เปิดอ่านรายการที่เลือกได้ตรงรายการ ไม่สลับไปยังรายการอื่น
- เจ้าของแก้ไขข้อมูลแล้วรายการเดิมถูกปรับปรุง โดยคง ID และเจ้าของเดิม และไม่สร้างรายการซ้ำ
- ถ้าเปลี่ยนรายวิชา รายการไปอยู่ในวิชาใหม่และไม่แสดงในวิชาเดิม
- เจ้าของลบรายการได้หลังยืนยัน และรายการหายจากหน้าที่เกี่ยวข้องหลังโหลดใหม่
- การยกเลิกลบไม่ทำให้ข้อมูลเปลี่ยนแปลง
- ผู้ใช้ที่ไม่ใช่เจ้าของไม่มีสิทธิ์แก้ไขหรือลบ ทั้งผ่านหน้าจอ URL หรือคำขอ Backend
- ข้อมูลไม่ถูกต้องหรือการบันทึกล้มเหลวต้องไม่แสดงว่าสำเร็จ และข้อมูลเดิมต้องยังอยู่
- เมื่อไม่มีรายการ ระบบแจ้งสถานะอย่างชัดเจนและมีทางไปหน้าสร้างรายการ

## 5. Demo Script สำหรับสาธิต

### 5.1 เตรียมก่อนเริ่ม Demo

1. ใช้โค้ดรุ่นเดียวกันทั้ง Frontend และ Backend และจด commit ไว้
2. เตรียมบัญชีเจ้าของ บัญชีผู้ใช้อื่น และรายการตั้งต้นตามหัวข้อ 2
3. เปิด Backend และ SQL Server ตรวจ Login และยืนยันว่าโหลดรายการผ่าน API ก่อนเริ่ม
4. เปิดหน้า `shared-courses.html` ซึ่งมีส่วนจัดการแนวข้อสอบของฉัน หรือเปิดหน้าที่ทีมกำหนดไว้สำหรับรายการของผู้ใช้
5. ใช้ชื่อรายการที่มีคำว่า `UAT` เพื่อแยกจากข้อมูลจริง และไม่เปิดเผยรหัสผ่านหรือ token บนหน้าจอ

### 5.2 สาธิตดูและเปิดอ่านรายการ

| ลำดับ | ผู้สาธิตทำอะไร | สิ่งที่ควรเห็น |
|---|---|---|
| 1 | Login ด้วยบัญชีเจ้าของ | เข้าสู่ระบบสำเร็จและชื่อผู้ใช้ถูกต้อง |
| 2 | เปิดหน้าแนวข้อสอบของฉัน | เห็นเฉพาะรายการของผู้ใช้ปัจจุบัน |
| 3 | เลือกรายการ `แนวข้อสอบ CS261 สำหรับทดสอบการจัดการ` | เปิดรายละเอียดของรายการที่เลือก ไม่ใช่รายการอื่น |
| 4 | เปรียบเทียบข้อมูลกับข้อมูลตั้งต้น | วิชา ปี ภาคเรียน ช่วงสอบ รูปแบบ จำนวนข้อ หัวข้อ และเจ้าของตรงกัน |

### 5.3 สาธิตแก้ไขรายการ

1. จากรายการเดิมกด `แก้ไขข้อมูล`
2. เปลี่ยนชื่อเป็น `แนวข้อสอบ CS261 ฉบับแก้ไข UAT` และเปลี่ยนหัวข้อ/จำนวนข้อ
3. กดบันทึกหนึ่งครั้ง
4. แสดงข้อความแก้ไขสำเร็จ และตรวจว่ารายการเดิมมีข้อมูลใหม่
5. โหลดหน้าใหม่ เปิดหน้าอ่าน และเปิดหน้ารายวิชาเพื่อตรวจว่าข้อมูลล่าสุดยังอยู่
6. เปลี่ยนวิชาเป็น CS102 ที่มีในระบบ แล้วแสดงว่ารายการย้ายจาก CS261 ไป CS102 โดยไม่สร้างสำเนา

### 5.4 สาธิตข้อมูลผิดพลาดและสิทธิ์

1. เปิดแก้ไขรายการแล้วลบชื่อหรือหัวข้อ กดบันทึก
2. แสดงข้อความเตือน และยืนยันว่าข้อมูลเดิมยังอยู่
3. เปลี่ยนเป็นบัญชีคนที่ 2 แล้วลองเข้าถึงรายการของบัญชีคนที่ 1
4. แสดงว่าปุ่มหรือคำขอแก้ไขถูกปฏิเสธ และรายการเดิมไม่เปลี่ยน

### 5.5 สาธิตลบและยกเลิกการลบ

1. กลับเข้าบัญชีเจ้าของและเลือกรายการทดสอบ
2. กด `ลบรายการ` แล้วเลือก `ยกเลิก` เพื่อแสดงว่ารายการยังอยู่
3. กดลบอีกครั้งแล้วเลือก `ยืนยันลบรายการ`
4. แสดงข้อความลบสำเร็จ โหลดหน้าใหม่ และตรวจว่ารายการหายจากหน้าของฉัน/หน้าวิชา
5. ลองเปิดลิงก์เดิมเพื่อแสดงว่าไม่พบรายการหรือรายการถูกลบแล้ว

### 5.6 สาธิตกรณี Login หรือ Backend มีปัญหา

1. ทำให้ Login หมดอายุหรือหยุด Backend ตามวิธีที่ทีมเตรียมไว้
2. ลองบันทึกการแก้ไขหรือลบรายการ
3. แสดงข้อความผิดพลาดที่เข้าใจได้ และยืนยันว่าไม่มีข้อความสำเร็จ
4. เปิดระบบกลับ แล้วตรวจข้อมูลก่อนดำเนินการซ้ำเพื่อไม่ให้เกิดรายการซ้ำหรือการลบซ้ำ

## 6. สิ่งที่ต้องเห็นในตอนจบ Demo

- แต่ละบัญชีเห็นรายการของตนเองถูกต้อง
- เปิดอ่าน แก้ไข ย้ายวิชา ลบ และยกเลิกการลบได้ตามสิทธิ์
- ข้อมูลผิดพลาดไม่ทำให้ข้อมูลเดิมเสียหาย
- ผู้ไม่ใช่เจ้าของแก้ไขหรือลบไม่ได้
- ผลที่เห็นมาจาก API และฐานข้อมูลจริง ไม่ใช้รายการจำลองในเบราว์เซอร์
- ผลจริง หลักฐาน และการตัดสินใจของ PO ถูกบันทึกแยกจากผลคาดหวัง
