# Task8: U1 แผนทดสอบการเข้าสู่ระบบ

## วัตถุประสงค์

ตรวจสอบว่านักศึกษามหาวิทยาลัยธรรมศาสตร์สามารถเข้าสู่ระบบด้วยบัญชี TU ที่มีอยู่ได้อย่างถูกต้อง โดยไม่ต้องสมัครบัญชีใหม่ และระบบสามารถจัดการกรณีเข้าสู่ระบบไม่สำเร็จ ตรวจสอบสิทธิ์ผู้ใช้ ป้องกันการเข้าถึงเนื้อหาโดยผู้ไม่มีสิทธิ์ และรักษาข้อมูลผลงานของบัญชีเดิมได้

## ขอบเขตการทดสอบ

- การแสดงผลและการกรอกข้อมูลบนหน้า Login (UI)
- การตรวจสอบข้อมูลเข้าสู่ระบบผ่าน Backend และ TU API (API)
- การค้นหาและจัดการข้อมูลผู้ใช้ภายใน (DAO)
- การเชื่อมต่อระหว่าง UI กับ API
- การเชื่อมต่อระหว่าง API กับ DAO
- การทดสอบระบบโดยรวม (System Test)
- การทดสอบการยอมรับจากผู้ใช้และการตรวจรับจาก PO (UAT)
- การตรวจสอบความปลอดภัยและการคงอยู่ของข้อมูลผู้ใช้

## เงื่อนไขก่อนทดสอบ

1. ระบบ Frontend และ Backend พร้อมใช้งาน
2. มีบัญชีทดสอบนักศึกษา TU ที่สามารถยืนยันตัวตนได้
3. สามารถจำลองกรณีบัญชีหรือรหัสผ่านไม่ถูกต้อง บัญชีไม่ Active และ TU API ขัดข้องได้
4. มีข้อมูลผู้ใช้ภายในและผลงานแนวข้อสอบสำหรับทดสอบการเข้าสู่ระบบซ้ำ
5. ผู้ทดสอบสามารถเปิดหน้า Login และตรวจสอบผลตอบกลับจากระบบได้

## Test Cases

### U1-TC01: นักศึกษา TU เข้าสู่ระบบสำเร็จ

**หัวข้อทดสอบ:** UI, API, UI-API, API-DAO, System Test, UAT

**ข้อมูลทดสอบ / ขั้นตอน:**
1. เปิดหน้า Login
2. กรอกบัญชีและรหัสผ่านนักศึกษา TU ที่ถูกต้อง
3. กดเข้าสู่ระบบและตรวจสอบผลตอบกลับ
4. ตรวจสอบหน้าหลักและข้อมูลโปรไฟล์

**ผลลัพธ์ที่คาดหวัง:**
- ระบบแจ้งเข้าสู่ระบบสำเร็จและเปิดหน้าหลักที่ค้นหาวิชาได้
- ผู้ใช้สามารถใช้งานในฐานะบัญชีของตนเอง
- ไม่แสดงหรือเก็บรหัสผ่าน TU ในข้อมูลโปรไฟล์

### U1-TC02: บัญชีหรือรหัสผ่านไม่ผ่านการยืนยัน

**หัวข้อทดสอบ:** UI, API, UI-API, System Test, UAT

**ข้อมูลทดสอบ / ขั้นตอน:**
1. ทดสอบด้วยรหัสผ่านผิด
2. ทดสอบด้วยบัญชีที่ TU API ปฏิเสธ
3. ทดสอบด้วยบัญชีที่มีสถานะไม่ Active
4. ตรวจสอบข้อความแจ้งผลและการเข้าถึงเนื้อหา

**ผลลัพธ์ที่คาดหวัง:**
- ทุกกรณีเข้าสู่ระบบไม่สำเร็จ
- ไม่อนุญาตให้เข้าถึงเนื้อหาที่ต้อง Login
- ไม่แสดงรหัสผ่านในข้อความแจ้งผล

### U1-TC03: กรอกข้อมูลเข้าสู่ระบบไม่ครบ

**หัวข้อทดสอบ:** UI, API, UI-API, System Test

**ข้อมูลทดสอบ / ขั้นตอน:**
1. ทดสอบเว้นบัญชี
2. ทดสอบเว้นรหัสผ่าน
3. ทดสอบเว้นทั้งสองช่อง
4. ทดสอบกรอกบัญชีเป็นช่องว่างล้วน
5. ตรวจสอบการจัดการช่องว่างของบัญชีและรหัสผ่าน

**ผลลัพธ์ที่คาดหวัง:**
- ระบบแจ้งให้กรอกข้อมูลที่จำเป็น
- ไม่ส่งข้อมูลที่ไม่ครบไปยัง TU API
- ไม่อนุญาตให้เข้าสู่ระบบ
- ตัดช่องว่างของชื่อบัญชีตามข้อกำหนดโดยไม่เปลี่ยนค่ารหัสผ่าน

### U1-TC04: บัญชีอาจารย์หรือบุคลากรเข้าใช้ไม่ได้

**หัวข้อทดสอบ:** API, UI-API, API-DAO, System Test, UAT

**ข้อมูลทดสอบ / ขั้นตอน:**
1. ทดสอบด้วยบัญชีอาจารย์
2. ทดสอบด้วยบัญชีบุคลากร
3. ตรวจสอบประเภทบัญชีจากผลตอบกลับของ TU API
4. ตรวจสอบสิทธิ์การเข้าถึงเนื้อหา

**ผลลัพธ์ที่คาดหวัง:**
- ระบบแจ้งว่าใช้ได้เฉพาะนักศึกษา TU
- ไม่อนุญาตให้เข้าใช้เนื้อหา แม้รหัสผ่านถูกต้อง

### U1-TC05: TU API ไม่พร้อมใช้งาน

**หัวข้อทดสอบ:** API, UI-API, System Test

**ข้อมูลทดสอบ / ขั้นตอน:**
1. กรอกข้อมูลเข้าสู่ระบบ
2. จำลองให้ TU API ไม่ตอบกลับหรือเกิดข้อผิดพลาด
3. ตรวจสอบข้อความแจ้งผลและสถานะการเข้าสู่ระบบ

**ผลลัพธ์ที่คาดหวัง:**
- แจ้งว่าไม่สามารถยืนยันบัญชีได้ในขณะนี้และให้ลองภายหลัง
- ไม่สรุปว่ารหัสผ่านผิด
- ไม่แจ้งเข้าสู่ระบบสำเร็จและไม่ข้ามการยืนยันตัวตน

### U1-TC06: ยืนยันไม่ได้ว่าบัญชีเป็นนักศึกษา

**หัวข้อทดสอบ:** API, API-DAO, System Test

**ข้อมูลทดสอบ / ขั้นตอน:**
1. จำลองผลตอบกลับจาก TU API ที่ขาดข้อมูลสถานะหรือประเภทบัญชี
2. ให้ระบบตรวจสอบผลการยืนยันตัวตน
3. ตรวจสอบสิทธิ์และข้อมูลผู้ใช้ที่เกี่ยวข้อง

**ผลลัพธ์ที่คาดหวัง:**
- แจ้งว่าไม่สามารถยืนยันสิทธิ์ได้
- ไม่อนุญาตให้เข้าใช้เนื้อหา
- ไม่ให้สิทธิ์ผู้ใช้โดยอัตโนมัติเมื่อข้อมูลยืนยันไม่เพียงพอ

### U1-TC07: ผู้ที่ไม่ได้เข้าสู่ระบบเข้าใช้ส่วนที่ป้องกันไว้ไม่ได้

**หัวข้อทดสอบ:** API, API-DAO, System Test, UAT

**ข้อมูลทดสอบ / ขั้นตอน:**
1. ทดสอบผู้ที่ยังไม่ Login
2. ทดสอบ Session ที่หมดอายุหรือถูกดัดแปลง
3. ทดลองเปิดหน้าเว็บและส่งคำขอ Backend เพื่อค้นหา/เปิดวิชา ดูรายการของฉัน เผยแพร่ แก้ไข และลบข้อมูล โดยทดสอบแยกแต่ละการกระทำ

**ผลลัพธ์ที่คาดหวัง:**
- หน้าเว็บพาไป Login ตามการออกแบบ
- Backend ปฏิเสธทุกการกระทำที่ต้องใช้สถานะ Login ที่ถูกต้อง
- ไม่ส่งเนื้อหาที่ต้อง Login กลับมา
- ไม่สร้าง แก้ไข หรือลบข้อมูลเดิม

### U1-TC08: เข้าสู่ระบบซ้ำด้วยบัญชีเดิมยังเห็นผลงานเดิม

**หัวข้อทดสอบ:** DAO, API-DAO, UI-API, System Test, UAT

**ข้อมูลทดสอบ / ขั้นตอน:**
1. เตรียมบัญชีที่เคยเผยแพร่แนวข้อสอบไว้ในระบบ
2. เปิด Session ใหม่
3. เข้าสู่ระบบด้วยบัญชี TU เดิม
4. เปิดหน้าแนวข้อสอบของฉันและตรวจสอบผลงาน

**ผลลัพธ์ที่คาดหวัง:**
- ระบบใช้ผู้ใช้ภายในคนเดิม
- ไม่สร้างบัญชีซ้ำ
- หน้าแนวข้อสอบของฉันยังแสดงผลงานที่เคยเผยแพร่

## เกณฑ์ผ่าน

- U1-TC01 ถึง U1-TC08 ต้องทำงานตามผลลัพธ์ที่คาดหวัง
- ผู้ใช้ที่ไม่ผ่านการยืนยันหรือไม่มีสิทธิ์ต้องไม่สามารถเข้าสู่ระบบหรือเข้าถึงเนื้อหาที่ป้องกันไว้ได้
- ระบบต้องไม่ข้ามการยืนยันตัวตนเมื่อ TU API ขัดข้องหรือข้อมูลไม่เพียงพอ
- ต้องไม่มีรหัสผ่าน TU ถูกจัดเก็บในข้อมูลโปรไฟล์หรือเปิดเผยในข้อความแจ้งผล
- การเข้าสู่ระบบซ้ำต้องไม่สร้างบัญชีซ้ำและต้องยังเห็นผลงานเดิม
- ผลการทดสอบจริงต้องบันทึกหลังดำเนินการทดสอบเท่านั้น
